# 航空结构件加工质量数据治理与 AI 数控编程 · 可运行演示

一个**可直接跑通、可直接展示**的端到端演示：从多源加工过程数据接入，到数据治理与质量分析，再到 AI 数控编程（切削区域分割 + 参数推荐）。

> ### ⚠️ 数据合规声明
>
> 本项目使用**100% 合成数据（synthetic data）**。所有零件号、工序、缺陷模式、材料、
> 切削参数、工艺路线均由 `src/synthetic/generator.py` 以固定随机种子程序化生成，
> **不包含任何真实工程数据、图纸、工艺文件或企业信息**。
>
> 演示目的在于说明**方法、数据流与工程实现**，其中的指标均为合成语料上的计算结果，
> 不代表任何真实产线表现。

对应简历中的两个航空工业成飞项目（**注意：目录编号与简历项目编号是反序的**，见下表）。

| 简历项目 | 时间 | 本仓库目录 | 内容 |
|---|---|---|---|
| **项目 2** 复杂结构件加工过程质量数据治理与工艺流程分析 | 2024.4–2025.8 | `src/project1_governance/` | 双通道接入、湖仓分层、240 条规则稽核、健康分、典型工艺路线挖掘、贝叶斯根因归因 |
| **项目 1** 飞机结构件数控编程 AI 模型构建技术 | 2025.8–至今 | `src/project2_nc/` | B-rep 属性图构建、GAT 加工区域分割、区域级切削参数回归 |

`project2_nc` 是"AI 数控编程"项目（简历里的项目 1）。

## 二、三步跑起来

```bash
pip install -r requirements.txt   # 1. 装依赖
python run_all.py                 # 2. 跑端到端流水线，产出 11 个 parquet
streamlit run app.py              # 3. 打开交互看板
```

`run_all.py` 的常用参数：

```bash
python run_all.py            # demo 规模（推荐，约 2 分钟），复用已缓存的 GAT 权重
python run_all.py --quick    # 极小语料，用于快速验证，不训练
python run_all.py --full     # 全量 46 万条语料
python run_all.py --train    # 强制重新训练 GAT，而不是复用缓存权重
python run_all.py --defect 腹板变形   # 指定要归因的缺陷模式
```

第 3 步依赖第 2 步产出的 `outputs/*.parquet`；看板本身只读结果文件，不重算。

> **耗时说明**（本机实测，仅供参考，机器越快越短）：
>
> | 命令 | 耗时 | 说明 |
> |---|---|---|
> | `python run_all.py` | **约 130 秒** | 默认路径。前提是 `outputs/weights/gat_weights.npz` 存在 —— 该缓存权重随仓库一起提交，直接复用即可 |
> | `python run_all.py --quick` | 约 155 秒 | 极小语料 + 仅 60 个 epoch，用于快速验证链路通不通，指标会明显偏低 |
> | `python run_all.py --train`（或删掉 `outputs/` 后重跑） | 约 940 秒 | GAT 从零训练 600 个 epoch，结果有小幅浮动 |
>
> 想省时间就**不要删 `outputs/`** —— 它是流水线产物，随时可以删了再用默认命令重建。

## 四、技术实现

### 项目 2：质量数据治理与工艺流程分析（`src/project1_governance/`）

- **双通道接入** `ingest.py`：8 类数据源按 `stream`（CNC 采集 / 在线测量 OMP / MES 报工）与
  `batch`（刀具 / 三坐标 CMM / 视觉检测 / 物料 / 设备）分别接入，落到 80 张表
  （ODS 30 / DWD 30 / DWS 15 / ADS 5）。
- **240 条规则稽核** `audit.py`：六个质量维度、三个执行层级
  （接入层 160 / 存储层 60 / 服务层 20）。每条规则对应一个**真实物理校验**，
  分母取该维度**所属数据源的记录数**——DWD 是八源 union 宽表，若按全表行数做分母，
  单源缺陷会被稀释约 8 倍。
- **健康分** `health.py`：`100 × Σ(维度权重 × 规则通过率)`，并输出 COPQ 拆解与 FPY 汇总。
- **典型工艺路线挖掘** `route_mining.py`：熵加权多级 LCS → 谱嵌入 → KDE 估 K → PSO-Kmeans。
  一条记录只有在与簇共识工序链的相似度超过阈值（0.62）时才计入"被覆盖"，
  否则每条样本都会因归属某个簇而"覆盖"，覆盖率必然是毫无意义的 100%。
- **贝叶斯根因归因** `root_cause.py`：缺陷模式 → 关键工艺参数 → 关联工序 → 根因候选
  四层图谱，结构感知 CPT 做 Top-K 后验推断，并给出信息价值与建议动作。

### 项目 1：AI 数控编程（`src/project2_nc/`）

- **B-rep 属性图** `brep_graph.py`：面级 24 维节点特征（几何 / 拓扑 / 精度 / 材料），
  邻接面之间 5 维边特征（凹凸性、夹角、面积比、共面、边界类型）。
- **GAT** `gat_model.py`：加工区域分割建模为**边二分类**（同一加工区域 / 不同区域），
  三层 4 头注意力（隐层 32），Focal Loss（γ=2.0, α=0.65）处理边界样本极不均衡；
  分割结果再接区域级参数回归，输出主轴转速与进给速度。按**零件级**划分训练/验证集，
  避免同一零件的面同时出现在两侧造成泄漏。
- **物理门槛复核**：对模型推荐参数做功率 `P = kc·ap·ae·vf/60000`（上限 22 kW）
  与每齿进给 `fz = vf/(n·z)` 窗口校验，把超出工艺能力的推荐挡在输出之外。

> 说明：本演示**只包含推理**（前向计算），不包含训练流程 —— 仓库不引入 PyTorch /
> PyTorch Geometric，GAT 使用缓存权重在 numpy 上完成前向，用于说明模型结构与数据流。

### 数据估值（`src/common/data_valuation.py`）

LOO 留一法 + Shapley 值估计样本贡献，冗余折价采用**乘性有界折扣**
`V(S) = Σ v_i · (1 − 0.35 · share_i)`，避免绝对扣减在不同量纲下失控；
代理模型对 `y` 同样做标准化后反标准化，保证回归目标与 Shapley 值同量级。

## 五、实测结果（demo 规模，seed 固定可复现）

**数据治理**

| 指标 | 治理前 | 治理后 |
|---|---|---|
| 数据健康分 | 62.0 | **91.0** |
| 数据不一致率 | 18.6% | **3.4%** |

| 维度 | 治理前 | 治理后 | 降幅 |
|---|---|---|---|
| 完整性 | 24.5% | 7.2% | 71% |
| 有效性 / 值域 | 9.7% | 2.9% | 70% |
| 一致性 | 16.2% | 5.2% | 68% |
| 唯一性 | 7.1% | 2.1% | 71% |
| 及时性 | 30.7% | 9.8% | 68% |
| 准确性 | 4.7% | 1.3% | 72% |

**工艺流程分析**

- 典型工艺路线 **K = 18** 条，覆盖零件 **1,465 / 1,500**（覆盖率 **97.7%**）
- 缺陷 `DM-01` 的 Top-5 根因后验质量 **0.835**；首要根因为**进给速度漂移**
  （关键工艺参数 KPP-001，关联工序 OP-04），后验概率 **26.6%**
- 机理解释与观测交叉校验通过（相对误差 **0.105**）

**AI 数控编程**（80 个零件 / 15,749 个面 / 35,406 条边，缓存权重推理）

- 加工区域分割（边分类）：准确率 **0.832**、精确率 **0.825**、召回率 **0.820**、IoU **0.698**、AUC **0.913**
- 参数回归：转速 MAPE **3.2%**、进给 MAPE **1.7%**，R² **0.979 / 0.999**
- 物理门槛复核：模型推荐违规率 **0.97%**，平均切削功率 **8.82 kW**，平均每齿进给 **0.0496 mm/z**

> 上述数值为 `--full`/首次运行时重新训练的结果。治理侧指标由 `BASELINE_*` /
> `TARGET_*` 锚定、固定种子下完全可复现；GAT 侧数值会随语料规模变化而小幅浮动。

## 七、工程说明

- **随机种子固定**（`RANDOM_SEED`），同样参数重复运行结果一致。
- **看板不重算**：`app.py` 只读 `outputs/` 下的 parquet，打开即为流水线最后一次结果。
- **所有指标可回溯**：看板上的每个数字都来自 `outputs/` 中对应的 parquet，
  而非硬编码文案 —— 若两个位置的数字对不上，以 parquet 为准。
- `outputs/` 下内容全部为脚本产物，可随时删除后用 `python run_all.py` 重新生成。
